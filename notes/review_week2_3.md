## 교정받은 오개념: "내가 한 말" → 올바른 설명
- "arr + 1은 arr[0]에서 2바이트만큼 앞으로 간다" → `arr + 1`은 `&arr[1]`, 즉 2바이트 큰 주소다. 컴파일러가 1에 `sizeof(arr[0])`를 자동으로 곱하기 때문이다.
- "구조체와 클래스는 접근 권한이 다르다" → 다른 것은 기본(default) 접근 권한뿐이다(struct는 public, class는 private). C++에서는 둘 다 private 멤버와 멤버 함수를 가질 수 있다.
- (설명하지 못함) PWM 주파수와 분주비 → 아래 한 줄 정리 참고

## 한 줄 정리
- `sizeof(int)`: Nano(AVR)에서 int는 2바이트이고 PC에서는 보통 4바이트이므로, 크기가 중요한 곳에는 `int16_t` 같은 고정 크기 타입을 쓴다.
- `arr + 1`: 배열 이름은 식에서 `&arr[0]`로 바뀌고, `+1`은 요소 하나(`sizeof(arr[0])`바이트)만큼 큰 주소다.
- PWM: 핀은 항상 0V 또는 5V만 내보내며, 평균 전압은 duty × 5V(`analogWrite(127)`이면 약 2.5V)일 뿐 순간 전압이 2.5V인 때는 없다.
- 8비트 타이머와 분주비 64: 16MHz를 64로 나눈 250kHz로 타이머가 0~255를 세므로, Fast PWM(5·6번 핀, Timer0)은 16MHz / (64 × 256) ≈ 977Hz, Phase Correct PWM(3·9·10·11번 핀)은 왕복으로 세어 16MHz / (64 × 510) ≈ 490Hz다.
- `INPUT_PULLUP`: 핀을 칩 안의 풀업 저항(약 20~50kΩ, ATmega328P 데이터시트)으로 5V에 연결하는 모드다.
- 풀업 원리(분압): 핀 전압은 5V × R버튼 / (R풀업 + R버튼)이다. 버튼을 떼면 R버튼이 사실상 무한대여서 저항에 전류가 흐르지 않아 전압 강하가 없으므로 핀은 약 5V(HIGH)이고, 누르면 R버튼이 약 0Ω이어서 핀은 0V(LOW)다. 풀업이 없으면 뗀 상태에서 핀이 떠서(floating) 값이 무작위로 바뀐다.
- 구조체와 클래스: 기본 접근 권한만 다르고 기능은 같다.
- 참조(reference): 변수의 별명으로, 선언 때 반드시 초기화하고 다른 변수로 바꿀 수 없으며 `*` 없이 원본을 읽고 쓴다. 포인터는 주소를 저장하는 변수라 가리키는 곳을 바꿀 수 있고 null일 수 있다.

## 아직 모르는 것 / 다음에 확인할 것
- 분주비와 PWM 주파수 계산을 보지 않고 직접 하기 (이번에 설명하지 못함)
- Timer0은 `millis()`와 `delay()`도 쓰므로 그 분주비를 바꾸면 시간 함수가 틀어진다는 점
- Servo 라이브러리는 Timer1을 쓰므로, 서보를 쓰면 9·10번 핀의 `analogWrite`가 동작하지 않는다는 점
- 풀업에서 버튼을 눌렀을 때 흐르는 전류(5V / R풀업) 계산
- `&`의 세 가지 의미 구분: 식의 주소 연산자, 선언의 참조(`int &r = a;`), 비트 AND
- 참조로 swap 함수를 보지 않고 직접 쓰기

## V1에서 이 개념을 쓰는 곳
- RMS 윈도 버퍼: `int16_t` 정적 배열과 포인터 연산
- 서보 그리퍼: Servo 라이브러리(Timer1)를 쓰므로 PWM이 필요한 다른 출력은 9·10번 핀을 피해 배치
- 버튼 입력(예: 비상정지, 캘리브레이션 시작): `INPUT_PULLUP`으로 외부 저항 없이 연결하고, 눌림을 LOW로 판정

- 함수가 여러 값을 돌려줄 때(예: 2채널 RMS) 참조 매개변수 사용
