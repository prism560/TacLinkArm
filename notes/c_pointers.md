## 코드 1 — `&`와 `*` (09-30)

```c
#include <stdio.h>

int main(void) {
    int number = 10;
    int *p = &number;      // &number: number의 주소

    printf("number 주소 = %p\n", (void*)&number);
    printf("p 값        = %p\n", (void*)p);   // 같은 주소
    printf("*p          = %d\n", *p);         // p가 가리키는 값 → 10

    *p = 20;               // 포인터로 원래 변수 값을 바꿈
    printf("number      = %d\n", number);     // 20
    return 0;
}
```

**한 줄 설명:** `&`는 변수의 주소를 꺼내고, 포인터 앞에 붙인 `*`는 그 주소에 있는 값을 꺼낸다.

## 코드 2 — 포인터 연산과 배열 (10-01)

```c
#include <stdio.h>

int main(void) {
    long arr[3] = {10, 20, 30};
    long *p = arr;                 // arr은 첫 원소의 주소 &arr[0]

    // 1. 타입 크기
    printf("[1] sizeof(long) = %zu\n\n", sizeof(long));

    // 2. p와 p+1의 주소
    printf("[2] p     = %p\n", (void*)p);
    printf("    p + 1 = %p\n", (void*)(p + 1));
    printf("    주소 차이 = %td 바이트\n\n", (char*)(p + 1) - (char*)p);

    // 3. arr[i] 와 *(arr+i) 비교
    printf("[3] i | arr[i] | *(arr+i) | *(p+i) | &arr[i]\n");
    for (int i = 0; i < 3; i++) {
        printf("    %d |   %ld   |    %ld    |   %ld   | %p\n",
               i, arr[i], *(arr + i), *(p + i), (void*)&arr[i]);
    }
    return 0;
}
```

실행 결과 (64비트 Linux gcc 기준. 주소값은 실행할 때마다 다름):

```
[1] sizeof(long) = 8

[2] p     = 0x7ffe31287880
    p + 1 = 0x7ffe31287888
    주소 차이 = 8 바이트

[3] i | arr[i] | *(arr+i) | *(p+i) | &arr[i]
    0 |   10   |    10    |   10   | 0x7ffe31287880
    1 |   20   |    20    |   20   | 0x7ffe31287888
    2 |   30   |    30    |   30   | 0x7ffe31287890
```

**한 줄 설명:** 포인터에 1을 더하면(`p + 1`, `p++`) 주소가 1바이트가 아니라 가리키는 자료형 크기(`sizeof(*p)`)만큼 이동한다. 그래서 `arr[i]`, `*(arr + i)`, `*(p + i)`는 모두 같은 값이다.

## 코드 3 — swap: 값 전달 vs 포인터 전달 (10-01)

```c
#include <stdio.h>

void swap_value(int a, int b) {      // a, b는 x, y의 복사본
    int t = a; a = b; b = t;         // 복사본끼리만 바뀜
}

void swap_ptr(int *a, int *b) {      // a, b는 x, y의 주소
    int t = *a; *a = *b; *b = t;     // 그 주소에 있는 원본을 바꿈
}

int main(void) {
    int x = 1, y = 2;

    swap_value(x, y);
    printf("값 전달 후:     x=%d, y=%d\n", x, y);   // x=1, y=2 (그대로)

    swap_ptr(&x, &y);
    printf("포인터 전달 후: x=%d, y=%d\n", x, y);   // x=2, y=1 (바뀜)
    return 0;
}
```

**한 줄 설명:** 값으로 넘기면 함수는 복사본을 받기 때문에 원본이 그대로이고, 주소로 넘기면 함수가 그 주소로 찾아가 원본을 직접 바꾼다.

비유: 값 전달은 서류의 **복사본**을 건네는 것이다. 내용은 똑같이 다 들어 있지만 복사본에 낙서해도 원본은 그대로다. 포인터 전달은 원본이 있는 **집 주소**를 건네는 것이라, 그 주소로 찾아가 원본을 직접 고칠 수 있다.

## 오늘 알게 된 것·고친 것
- 처음 코드에서는 `long` 값을 `%d`로 출력했다. `long`은 `%ld`로 출력해야 한다(`gcc -Wall`로 컴파일하면 경고가 나온다). 첫 줄 라벨도 `sizeof(int)`에서 `sizeof(long)`으로 고쳤다.
- `long`의 크기는 환경마다 다르다. 64비트 Linux에서는 8바이트이고, Windows에서는 4바이트다. Arduino Nano(AVR)에서는 `int`가 2바이트, `long`이 4바이트다. → MCU 코드에서는 크기가 정해진 `int16_t`, `uint32_t` 같은 타입을 쓰는 이유.

## 1주차 AI 튜터 교정 (2026-10-05)
- 주제: 포인터(`&`, `*`), 포인터 연산, 배열과 포인터, swap, 스택/힙과 정적 할당
- 교정받은 오개념(1~3개): "내가 한 말" → 올바른 설명
  - "`*`은 포인터가 가리키고 있는 값을 불러온다" / "주소를 보내면 전체 코드에서 값이 변한다" → `*p`는 p가 가리키는 변수 그 자체다. `=`의 오른쪽에 있으면 읽고, 왼쪽에 있으면 쓴다. 주소를 넘기는 것만으로는 원본이 바뀌지 않고, 함수 안에서 `*pa = ...`처럼 역참조로 써야 바뀐다. `pa = pb;`는 지역 포인터가 가리키는 곳만 바꾼다.
  - "`p + 1*sizeof(type)`", "`arr+i*sizeof(arr)`" → 코드에는 `p + 1`, `arr + i`만 쓴다. 크기 곱셈은 컴파일러가 자동으로 하므로 직접 곱하면 이중으로 이동한다. 기준 크기는 포인터가 가리키는 대상 타입의 크기(`sizeof(*p)`)이고, `sizeof(arr)`는 요소 하나가 아니라 배열 전체의 바이트 수다.
  - "배열 arr은 그 자체로 arr[0]의 포인터 값을 가진다" → 배열은 포인터가 아니다. 식에서 첫 요소의 주소(`&arr[0]`)로 변환(decay)될 뿐이며, `sizeof(arr)`에서는 변환되지 않는다. 함수에 넘긴 뒤에는 포인터가 되어 `sizeof`가 2(Nano의 포인터 크기)를 돌려준다.
- 한 줄 정리(개념마다 한 문장):
  - `&`: 주소 연산자(address-of)로, 변수의 주소를 만든다.
  - `*`: 역참조(dereference) 연산자로, 그 주소에 있는 변수를 읽거나 쓴다.
  - 포인터 연산: `p + 1`은 `sizeof(*p)`바이트 큰 주소(다음 요소)이며 p를 바꾸지 않고, `p++`는 p를 바꾼다.
  - 배열과 포인터: `arr[i]`는 `*(arr + i)`와 같다.
  - swap: 포인터 전달도 값 전달이며 복사되는 값이 주소일 뿐이고, `*`로 그 주소에 가서 써야 main의 변수가 바뀐다.
  - 스택(stack)과 힙(heap): 스택은 함수 호출 때 자동으로 쌓였다 사라지고, 힙은 `malloc`/`free`로 직접 관리한다.
  - 정적 할당: Nano(SRAM 2KB)는 메모리 보호가 없고 힙이 조각나기 쉬우므로, 버퍼는 크기가 컴파일 때 확정되는 전역 또는 `static` 배열로 둔다.
- 아직 모르는 것 / 다음에 확인할 것:
  - `*p`가 `=`의 왼쪽에 올 때의 쓰기 (확인 질문 5개 중 3·4번을 틀림, 5번은 맞힘)
  - Nano에서 `sizeof(int)`는 2라는 점 (1번을 틀림)
  - 배열 밖을 읽어도 오류가 나지 않고 그 주소의 값이 그대로 나온다는 점(정의되지 않은 동작, undefined behavior)
  - 선언의 `*`(`int *p`, 타입 표기)와 식의 `*`(역참조)의 구분 (내 설명에서 빠짐)
  - swap 함수 본문을 보지 않고 직접 쓰기 (내 설명에서 빠짐)

  - 라이브러리 함수에 주소를 넘기는 코드 읽기(예: `begin(&Wire)`)
  - 3주차 C++ 참조(`&`)의 전제
  - 환경마다 크기가 다른 `int` 대신 `int16_t` 같은 고정 크기 타입 쓰기

## 3주차 약점 재확인 (2026-10-12)
- 오답: Nano에서 `sizeof(int)`는 4가 아니라 2다(AVR 8비트, int 16비트 / 4바이트는 `long`). 그래서 `int arr[3]`에서 `&arr[0]`이 0x100이면 `arr + 1`은 0x102다.
- 보완: 함수 안에서 포인터 변수 자체(`q = &y`)를 바꾸는 것은 복사본만 바꾸는 것이라 원본이 그대로이고, 원본을 바꾸려면 `*q = 값`처럼 가리키는 곳에 써야 한다.
